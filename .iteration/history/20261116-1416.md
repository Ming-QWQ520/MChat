## 第 2 轮：启动闪退修复 + CI 发布门禁（用户反馈驱动）

- 触发时间：2026-11-16 14:16（本地手动）

- 版本号：0.1.0 / 1（锁定，未改动）
- 类型：缺陷修复 + CI 基建增强（非 backlog 功能轮，backlog 不勾选）

### 根因（已用模拟器复现并拿到完整堆栈）

`core-prompt/TemplateEngine.kt` 构造函数中的模板变量正则：

```
Regex("\\{\\{\\s*([A-Za-z0-9_]+)\\s*}}")   // 修复前
```

尾部 `}}` 未转义。桌面 JVM 容忍未转义的 `}`（按字面量处理），但 **Android 的 ICU 正则
（`com.android.icu.util.regex.PatternNative`）严格要求 `}` 必须写成 `\}\}`**，
否则抛 `PatternSyntaxException`。

崩溃链路：`MainActivity` → Compose 首帧 → `ChatScreen` → `hiltViewModel()` 创建
`ChatViewModel` → Hilt 构造单例 `TemplateEngine` → 正则编译抛异常 → main 线程
FATAL EXCEPTION → 启动即闪退。debug / release 两个变体、API 30 / 34 均复现。

**第 0/1 轮漏网原因**：本地单元测试（JVM）与 Gradle 编译均无法暴露该问题——这正是
「单测绿、真机炸」的典型盲区。

### 定位手段：新增 smoke-test.yml（本轮核心基建）

`.github/workflows/smoke-test.yml`：GitHub 托管 runner 的 KVM 模拟器启动冒烟测试。

- 矩阵：API 30（default 镜像）+ API 34（google_apis 镜像），x86_64。
- 流程：`assembleDebug + assembleRelease` → 逐个安装 → `am start -W` 冷启动 →
  等待 30 秒 → `adb shell pidof` 检查进程存活 + crash buffer 无 `FATAL EXCEPTION`。
- 任一失败即整条 workflow 失败，并把 `logcat-*.log` / `crash-buffer-*.log` /
  `am-start-*.log` 作为 artifact 上传（本轮即通过该 artifact 拿到上述堆栈）。
- 首次运行（run 43812290847，commit cdc319d）：API 30 / 34 双双复现闪退，堆栈一致。

### 修复内容

1. `core-prompt/TemplateEngine.kt`：`}}` → `\}\}`（JVM 与 Android ICU 双兼容），
   附注释说明原因，防止回归。
2. `feature-chat/components/MarkdownText.kt`：标题解析 `Regex(...).find(...)!!` 的
   NPE 隐患——`#####`（5 个井号）或 `#无空格` 行会崩溃。改为 null 安全分支，
   不匹配时按普通段落渲染。（静态审查发现的同类隐患，顺带修复）

全仓库正则审计：除 TemplateEngine 外，其余 22 处 `Regex(...)` 均无未转义 `}`，
合法量词（`{1,4}`、`{3,}` 等）不受影响。

### CI 增强：发布门禁

`android-ci.yml` 新增 `smoke` job（`uses: ./.github/workflows/smoke-test.yml`），
`build` job 改为 `needs: smoke`——**APK 必须先在模拟器上通过冷启动测试，才会构建并
上传 latest-ci Release**。触发方式保持仅 workflow_dispatch（自检项 4 未违反）。
